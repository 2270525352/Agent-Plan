# 执行反馈日志

## 文档用途

记录主线 AI 每一次执行、每一次自检、以及支线合流后的真实结果。这是「分清楚执行反馈」的载体，也是定时测试对照真实改动、判断是否跑偏的依据。

## 规则

- 只追加，不改写历史记录。
- 每个任务至少一条；每次自检也追加一条。
- 如果本次执行使用了支线智能体,必须写关联支线 ID 和合流状态。
- 必须如实写验收/测试结果，红了就写红，不许粉饰。
- 实际改动文件必须与任务允许范围对得上；对不上要在「偏离/疑问」里写明。
- 没有对应反馈记录的执行，视为未完成。

## 记录格式

```text
反馈 ID：
时间：
对应任务 ID：
类型：任务执行 / 自检 / 支线合流回写 / 定时测试回写
关联支线 ID：
支线合流状态：无 / GREEN / YELLOW / RED
本次目标：
实际改动文件：
执行步骤回放：
验收命令与结果：PASS / FAIL +输出摘要
测试命令与结果：PASS / FAIL +输出摘要
对照真相源结论：一致 / 疑似偏离（指明哪条原话或契约）
偏离 / 疑问：
git 状态：clean / 已 checkpoint(commit) / 有未提交改动
状态：进行中 / 阻塞 / 完成
下一步：
```
