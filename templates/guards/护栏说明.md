# 护栏(把纪律变成硬约束)

Agent-Plan 其它文档靠「提示词请求 AI 配合」。这一层不一样:它把**能被脚本判定的纪律**交给 Claude Code hooks 和 git hooks **强制执行**,AI 不配合也绕不过去。

会跑偏的那个 AI,恰恰可能无视「请你别」。所以凡是机器能判定的,就别只靠 prompt。

## 装了什么、装在哪

| 文件 | 类型 | 作用 | 对谁生效 |
|---|---|---|---|
| `.claude/hooks/scope-guard.py` | Claude Code `PreToolUse` | 改到任务允许范围外 / 禁止范围 / 受保护真相源的文件,写入瞬间直接拒绝 | 仅 Claude |
| `.claude/hooks/feedback-stop-check.py` | Claude Code `Stop` | 有未提交业务改动却没写执行反馈就想结束,挡一次 | 仅 Claude |
| `.githooks/pre-commit` | git | 用户原话只追加;提交业务码必须有当前任务 + 执行反馈;跑该任务验收/测试 | Claude & Codex |
| `.githooks/pre-push` | git | 禁止 push 到 `main` / `master` | Claude & Codex |
| `.githooks/commit-msg` | git | 强制 `<任务号> (Claude/Codex): <简述>` | Claude & Codex |
| `docs/agent-plan/04-execution/current-task.json` | 运行态 | 护栏的判定依据:当前任务的 allow / forbid / 验收 / 测试 | — |

> **Claude vs Codex 强度不同(重要):** scope-guard、feedback 这两道**实时闸**用的是 Claude Code 的 hook 机制,**只在跑 Claude 时生效**。Codex 没有等价 hook,它那侧的硬约束全部落在 git hooks(提交 / 推送时)。所以跑 Codex 时,「改错文件」在写入瞬间拦不住,但**提交不进去**——把 checkpoint 节奏调密(每个任务一提交)就能尽早撞墙。

## 安装

优先用 skill 自带脚本安装,不要手工复制:

```bash
python3 <Agent-Plan技能目录>/scripts/agent-plan-guards.py install --project <目标项目>
python3 <Agent-Plan技能目录>/scripts/agent-plan-guards.py verify --project <目标项目>
```

这个脚本会做下面这些:

1. 把 `templates/guards/hooks/*.py` 拷到目标项目 `.claude/hooks/`。
2. 把 `templates/guards/githooks/*` 拷到 `.githooks/`,并设为可执行。
3. 把 `templates/guards/settings.hooks.json` 的 `hooks` 段合并进项目 `.claude/settings.json`(已有 hooks 只追加 Agent-Plan 条目,不整段覆盖)。
4. 把 `current-task.json` 放到 `docs/agent-plan/04-execution/current-task.json`。
5. 如果项目没有 `core.hooksPath`,自动设置为 `.githooks`。
6. 如果项目已有非 `.githooks` 的 `core.hooksPath`(Husky / lefthook / pre-commit / 自定义 hooks),默认**不覆盖**。请把 `.githooks/pre-commit`、`.githooks/commit-msg`、`.githooks/pre-push` 串到已有 hook 系统里;只有得到用户明确许可时,才用 `--force-hooks-path` 接管。
7. 需要 `python3`(hook 解析 JSON 用)。没有 python3 时,git 的 append-only / 主分支 / 提交格式三项照常,任务门禁会自动跳过并告警。

已有 hook manager 且已经手动串联 Agent-Plan hooks 时,校验用:

```bash
python3 <Agent-Plan技能目录>/scripts/agent-plan-guards.py verify --project <目标项目> --allow-existing-hooks-path
```

并把串联方式记到本文档,例如 Husky 的 `.husky/pre-commit` 调用了 `.githooks/pre-commit`。

> 若目标项目把 `.claude/` 加进了 `.gitignore`,给 hook 留个例外(`!.claude/hooks/`、`!.claude/settings.json`)好让团队共享;不共享也行,hook 在本地照样跑(它不依赖被提交)。`.githooks/` 默认不受影响。

## 卸载

只移除 Agent-Plan 自己安装的 hook 文件和 `.claude/settings.json` 里的 Agent-Plan hook 条目:

```bash
python3 <Agent-Plan技能目录>/scripts/agent-plan-guards.py uninstall --project <目标项目>
```

如果该项目的 `.githooks` 确认只给 Agent-Plan 使用,可同时移除 git 配置:

```bash
python3 <Agent-Plan技能目录>/scripts/agent-plan-guards.py uninstall --project <目标项目> --unset-hooks-path
```

## current-task.json 怎么用(护栏的开关)

护栏靠它生效。**主线执行 AI 每开始一个任务,先把这个文件改成当前任务的实情**——这是执行循环的第 0 步:

```json
{
  "task_id": "T-P0-0001",
  "phase": "P0",
  "allow": ["src/**", "tests/**"],
  "forbid": ["docs/agent-plan/00-source/**"],
  "protected": ["docs/agent-plan/00-source/用户原话文档.md"],
  "acceptance_cmd": "make accept",
  "test_cmd": "pytest -q",
  "updated_at": "2026-06-06T10:00:00"
}
```

- `task_id` 为空 = 护栏处于**规划态**,scope-guard 放行一切(规划期本来就要建文档、写原话);填上后进入**执行态**才开始拦。
- `allow` / `forbid` / `protected` 用 glob:`**` 跨目录,`*` 不跨 `/`,`?` 单字符,结尾 `/` 表示整个目录。
- `allow` 为空时,scope-guard 只查 forbid / protected,不限制其它文件;`allow` 非空时,范围外一律拒。
- `acceptance_cmd` / `test_cmd` 由 pre-commit 在提交业务码时跑,红了不让提交;留空则跳过并告警。

> 不更新 current-task.json,scope-guard 就一直放行。所以 goal 提示词把「更新 current-task.json」写成每个任务的第 0 步,定时审查也会核对它跟实际进度是否对得上。

## 校验(装完跑一遍,确认护栏真在挡)

- 先跑 `python3 <Agent-Plan技能目录>/scripts/agent-plan-guards.py verify --project <目标项目>`；已有 hook manager 时用 `--allow-existing-hooks-path`。
- 在 `00-source/用户原话文档.md` 删一行后 `git add` 再提交 → 应被 pre-commit 拒(只追加)。
- 提交信息写 `test` → 应被 commit-msg 拒。
- `git push origin main` → 应被 pre-push 拒。
- 跑 Claude,把 current-task.json 的 `allow` 设成 `["src/**"]`,让它改 `README.md` → scope-guard 应拒。

## 应急绕过

git hooks 全部认环境变量 `AGENT_PLAN_SKIP_HOOKS=1`,例如 `AGENT_PLAN_SKIP_HOOKS=1 git commit ...`。只在你清楚自己在干嘛时用。Claude hooks 可临时在 `.claude/settings.json` 注释掉。

## 局限(别把它当安全边界)

- 这是**防跑偏**,不是安全沙箱——能绕(环境变量、直接改 settings)。它挡的是「AI 自己走偏」,不是恶意对抗。
- scope-guard / feedback-stop-check 内部出错时**放行**(fail-open):坏 hook 不该把 agent 卡死。真正的兜底是 pre-commit(提交时)和定时审查(已提交分支)。
- feedback-stop-check 只挡一次(靠 `stop_hook_active` 防死循环),宁可漏报不可死循环。
