# 架构图

## 画图要求

- AI 必须把**本项目真实的系统架构**画进这份文档(Mermaid),让用户一眼看懂结构,不是放占位图。
- **每个部分都要标注职责**:这个模块/服务/层是干什么的、对谁负责、不负责什么。用户要看得见每一块在干嘛。
- 架构图要和 `总架构文档.md`、`总设计文档.md`、`接口契约文档.md` 对得上,不能各画各的。
- 改了架构就要同步更新图,图和文档不许脱节。

## 系统全景图

> 把下面替换成真实组件,节点文字写「名称:职责」。

```mermaid
flowchart LR
  Client["客户端: 发起请求 / 展示结果"] --> Entry["入口层: 鉴权、路由、参数校验"]
  Entry --> Core["核心服务: 业务逻辑(本项目主战场)"]
  Core --> Store["数据存储: 持久化、唯一真相数据"]
  Core --> External["外部服务: 第三方依赖(标明哪些不可控)"]
```

## 主线执行循环图

> 主线窗口怎么执行、怎么调用支线、怎么合流防跑偏。

```mermaid
flowchart LR
  Truth["真相源: 用户原话 / 需求 / 接口契约"] --> Main["主线窗口: 读真相源 → 选任务 → 更新 current-task"]
  Main --> Side{"需要支线协助?"}
  Side -->|否| Work["主线实现 / 测试"]
  Side -->|是| Contract["支线合同: 父任务 / 允许范围 / 验收 / 停止条件"]
  Contract --> Helper["支线智能体: 合同内实现 / 测试 / 审查"]
  Helper --> Merge["主线合流门禁: 完整性 / 范围 / 冲突 / 偏移度"]
  Merge --> Work
  Work --> Feedback["执行反馈日志 + 支线任务记录"]
  Feedback --> Check{"自检 + 定时测试: 对照真相源"}
  Check -->|一致| Commit["Git checkpoint"]
  Check -->|跑偏| Stop["停止 + 偏离报告"]
  Stop --> Truth
  Commit --> Main
```
