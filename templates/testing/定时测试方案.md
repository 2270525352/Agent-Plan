# 定时审查方案(外层兜底)

外层兜底:每 30 分钟,一个**独立审查代理**对照真相源检测主执行有没有跑偏。它跟主 goal 会话独立——主会话卡死、跑飞、结束,它照样准点跑,catch 主 AI 自己看不见的偏。

## 铁律:只检测、只记录,绝不擅自修改

审查代理**只检测、只记录**:发现问题就【只追加】写进问题文档 `../05-reviews/偏离用户原话报告.md`,**绝不自己改任何代码或文档**。这样审查本身不会把事情改坏,修复权留给主执行 / 用户。

## 为什么要外部定时

无论 Claude 还是 Codex,主执行 AI 都**没有可靠的内部定时器**(Codex 实测只能 `sleep` 阻塞硬撑,不发消息时不能自醒)。所以「每半小时」必须交给**外部调度**,且审查代理要**独立**(干净上下文,别带主执行的思路,不然自己查自己会把跑偏合理化)。

## 触发方式(按所用 AI 二选一)

- 跑 **Claude**:`ClaudeCode定时任务提示词.md` —— Claude Code `/schedule`(cron `*/30 * * * *`)。
- 跑 **Codex**:`CodexApp定时测试提示词.md` —— Codex App 定时任务(`RRULE:FREQ=HOURLY;INTERVAL=1;BYMINUTE=0,30;BYDAY=SU,MO,TU,WE,TH,FR,SA`)。

两套审查内容一致,只是调度器不同。定时任务都要跑在**项目目录**里。

## 启动顺序

**先挂定时审查,再开 goal。** 先有人盯着,再开始干,从第一分钟就抓跑偏。

## 每轮检测什么

1. 实现有没有偏离用户原话。
2. 改动有没有超出任务允许范围。
3. 有没有硬编码事实 / 价格 / 链接 / 话术 / 临时数据。
4. 进度跟文档(总任务、阶段)对不对得上。
5. 执行反馈日志跟真实 `git diff` 对不对得上。
6.（可跑则跑)项目测试与当前任务验收命令。

## 判级与处置

| 级别 | 含义 | 处置(只检测只记录) |
|---|---|---|
| GREEN | 没发现问题 | 记一行,放行 |
| YELLOW | 可疑、不确定 | 只追加写进偏离报告,提示主执行下轮自查;不强停 |
| RED | 确凿跑偏 / 测试红 | 只追加写进偏离报告并标 RED,**让主执行停下等用户确认** |

主执行的 goal 提示词里写了「每个任务前先看偏离报告有没有新 RED,有就停」——两层就靠这份问题文档对接。审查代理永远不替主执行修复。
