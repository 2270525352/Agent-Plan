# 定时审查方案(外层兜底)

外层兜底:一个**独立审查代理**对照真相源,检测主执行有没有跑偏。它跟主 goal 会话独立——主会话卡死、跑飞、结束,它照样跑,catch 主 AI 自己看不见的偏。

**审查单元是「每个任务的提交」,不是墙上时钟。** 主循环每完成一个任务就 checkpoint 提交并 push(见 `../06-goals/`),审查代理只看**已提交**的改动。定时器(cron / RRULE,默认每 30 分钟)是**心跳兜底**:保证即使没人盯着,最近完成的任务也会被审到。

## 铁律:只检测、只记录,绝不擅自修改

审查代理**只检测、只记录**:发现问题就【只追加】写进问题文档 `../05-reviews/偏离用户原话报告.md`,**绝不自己改任何代码或文档**。这样审查本身不会把事情改坏,修复权留给主执行 / 用户。

## 为什么要外部定时

无论 Claude 还是 Codex,主执行 AI 都**没有可靠的内部定时器**(Codex 实测只能 `sleep` 阻塞硬撑,不发消息时不能自醒)。所以这个心跳必须交给**外部调度**,且审查代理要**独立**(干净上下文,别带主执行的思路,不然自己查自己会把跑偏合理化)。

## 看的是已提交状态(关键,别踩这个坑)

定时审查代理(尤其 Claude Code `/schedule` 的远程代理、Codex App 任务)跑在**独立环境**,只能看到**已 push 的提交**——它**看不到主执行工作区里还没提交的改动**。所以:

- 审查的输入是**已提交的分支 diff**,不是本地工作区 `git diff`:
  - `git fetch -q origin`
  - `git diff <基线分支>...<任务分支>`(例如 `git diff origin/main...HEAD`)
  - `git log --oneline <基线分支>..<任务分支>`
- 这要求主循环**每个任务结束就提交 + push**(goal 提示词已写死)。一个任务期间的中间状态对审查者不可见——没关系,契约就是「一个任务 = 一次提交」,审查以任务为粒度。
- 如果某轮审查发现「一大堆未提交改动堆着、迟迟不提交」,这本身就是 YELLOW:主循环没按任务粒度提交,会让审查变瞎。

## 触发方式(按所用 AI 二选一)

- 跑 **Claude**:`ClaudeCode定时任务提示词.md` —— Claude Code `/schedule`(cron `*/30 * * * *`)。
- 跑 **Codex**:`CodexApp定时测试提示词.md` —— Codex App 定时任务(`RRULE:FREQ=HOURLY;INTERVAL=1;BYMINUTE=0,30;BYDAY=SU,MO,TU,WE,TH,FR,SA`)。

两套审查内容一致,只是调度器不同。定时任务都要跑在**项目目录 / 任务分支**里。

**想让审查跟着任务走(可选,更紧)**:在项目加一个 git `post-commit` 钩子,task checkpoint 提交就累加计数,每 N 次触发一次审查(或写个 `需审查` 标记文件让定时代理优先处理)。drift 跟任务进度相关、不跟时钟相关,事件驱动比纯墙钟更准;cron / RRULE 仍保留作心跳。

## 启动顺序

**先挂定时审查,再开 goal。** 先有人盯着,再开始干,从第一分钟就抓跑偏。

## 每轮检测什么

1. 实现有没有偏离用户原话。
2. 改动有没有超出任务允许范围(对照 `../04-execution/current-task.json` 的 allow / forbid)。
3. 有没有硬编码事实 / 价格 / 链接 / 话术 / 临时数据。
4. 进度跟文档(总任务、阶段)对不对得上。
5. 执行反馈日志跟**已提交的** `git diff <基线分支>...<任务分支>` 对不对得上(有没有漏写、谎报)。
6.(可跑则跑)项目测试与当前任务验收命令。
7. current-task.json 的 task_id 是否跟最近提交 / 反馈对得上(长期为空或停在旧任务 = 护栏可能没在生效)。

## 判级与处置

| 级别 | 含义 | 处置(只检测只记录) |
|---|---|---|
| GREEN | 没发现问题 | 记一行,放行 |
| YELLOW | 可疑、不确定、未按任务粒度提交 | 只追加写进偏离报告,提示主执行下轮自查;不强停 |
| RED | 确凿跑偏 / 测试红 | 只追加写进偏离报告并标 RED,**让主执行停下等用户确认** |

主执行的 goal 提示词里写了「每个任务前先看偏离报告有没有新 RED,有就停」——两层就靠这份问题文档对接。审查代理永远不替主执行修复。
