# 主线执行模式

## 适用条件

- 一个主线 AI / CLI 对话窗口（Claude 或 Codex）自主执行整份计划。
- 主线可以调用支线智能体协助局部实现、测试、审查或分析。
- 支线不得重新解释需求,不得绕过主线直接推进任务状态。
- 仍然需要 Agent-Plan 文档树和防偏离流程。
- 每个新窗口开始时必须先读项目根目录 `AGENTS.md`,再读 `CURRENT_STATE.md`,然后读 `docs/agent-plan/`。
- 防偏靠三层：主线自检（内部）+ 支线合流门禁（协作边界）+ 定时测试（外部兜底）；另有护栏（hooks + git）做硬执行。

## 执行循环

主线窗口反复走下面的循环，不许跳步：

1. 重读根级规则和状态：`AGENTS.md`、`CURRENT_STATE.md`。
2. 重读真相源：用户原话、用户强调事项、禁止偏离事项、AI可读需求、接口契约、总任务文档、任务说明。
3. 从总任务文档/任务说明选一个依赖已满足、未完成的任务。
4. 在 `CURRENT_STATE.md` 写入 active task / active writer / locked artifact / next action。
5. 核对任务的允许/禁止范围、验收命令、停止条件,并写进 `../04-execution/current-task.json`(task_id / allow / forbid / acceptance_cmd / test_cmd)——护栏靠它生效,不更新就不拦。
6. 执行前 `git status`。
7. 写最终成果文件前,重新读取 `CURRENT_STATE.md` 和目标文件磁盘最新版,确认没有其它窗口持有同一 artifact。
8. 判断是否需要支线协助。需要时先在 `../04-execution/支线任务记录.md` 写支线合同,并同步 `CURRENT_STATE.md`,再派发。
9. 只在允许范围内改动，按颗粒化步骤实现。
10. 支线返回后做合流门禁：完整性、范围、真相源追溯、接口/架构冲突、测试/验收、与其它支线冲突、偏移度。
11. 运行验收命令和测试。
12. 把结果如实追加到 `../04-execution/执行反馈日志.md`。没写反馈视为未完成。
13. 对照真相源自检：改动有没有超范围、有没有偏离原话或接口契约。
14. 父任务的所有支线都已合流 / 拒绝 / 阻塞并记录后,按 `../09-git/Git提交纪律.md` 做 checkpoint:**每个任务都提交 + push 到功能分支**(定时审查只看已提交的),并回写任务状态和 `CURRENT_STATE.md`。
15. 进入下一个任务。

## 支线协作

- 支线只做合同内的局部工作：实现、测试、审查、风险分析、方案比较。
- 支线合同必须写清父任务、来源需求、允许范围、禁止范围、验收标准、验证命令、停止条件。
- 支线输出返回后必须在 `../04-execution/支线任务记录.md` 写返回记录和主线合流门禁。
- 每次支线派发、返回、合流、拒绝或阻塞,都必须同步 `CURRENT_STATE.md`。
- 偏移度为 GREEN 才可直接合流；YELLOW 需要主线补齐；RED 必须停止父任务并报告。
- 不使用支线时,主线按同一循环独立执行。

## 自检节奏（内部第一道防线）

满足任一条件立即自检（重读真相源 + 跑验收/测试 + 写执行反馈）：

- 完成一个任务。
- 连续改动超过约 10 个文件或一大块逻辑。
- 准备做任何接近禁止范围的事。
- 对需求或边界产生任何不确定。

## 定时测试（外部兜底）

按 `../07-testing/定时测试方案.md` 配置：

- 跑 Claude：用 `../07-testing/ClaudeCode定时任务提示词.md`（Claude Code `/schedule`）。
- 跑 Codex：用 `../07-testing/CodexApp定时测试提示词.md`（Codex App 自动化）。

定时测试发现 RED 时，执行 AI 必须停下，按报告处理偏离后再继续。

## 护栏（硬执行）

本项目装了护栏（见 `../10-guards/护栏说明.md`）：改任务允许范围外的文件、改用户原话、提交格式不对、push 到 main，会被直接拦下。跑 Claude 有实时 hook + git 双层；跑 Codex 靠 git hook（提交时），所以更要每个任务都提交。护栏靠 `current-task.json` 判定范围——每个任务第 0 步先更新它。

## 停止条件

- 任务边界不清楚。
- 需求没有来源原话或确认文件。
- 需要修改禁止范围。
- 验收标准缺失或无法验证。
- 发现用户原话与任务冲突。
- 支线返回 RED 或无法验证。
- 支线结果之间互相冲突且主线无法裁决。
- 定时测试报告 RED 未处理。
- `CURRENT_STATE.md` 显示同一目标 artifact 被其它窗口锁定。
- 用户没有明确授权写入最终成果文件。
