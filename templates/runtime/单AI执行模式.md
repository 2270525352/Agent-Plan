# 单 AI 执行模式

## 适用条件

- 只有一个执行 AI（一个 Claude 或一个 Codex 窗口）自主执行整份计划。
- 仍然需要 Agent-Plan 文档树和防偏离流程。
- 防偏靠两层：AI 自检（内部）+ 定时测试（外部兜底）；另有护栏（hooks + git）做硬执行。

## 执行循环

单 AI 反复走下面的循环，不许跳步：

1. 重读真相源：用户原话、用户强调事项、禁止偏离事项、AI可读需求、接口契约、总任务文档、任务说明。
2. 从总任务文档/任务说明选一个依赖已满足、未完成的任务。
3. 核对任务的允许/禁止范围、验收命令、停止条件,并写进 `../04-execution/current-task.json`(task_id / allow / forbid / acceptance_cmd / test_cmd)——护栏靠它生效,不更新就不拦。
4. 执行前 `git status`。
5. 只在允许范围内改动，按颗粒化步骤实现。
6. 运行验收命令和测试。
7. 把结果如实追加到 `../04-execution/执行反馈日志.md`。没写反馈视为未完成。
8. 对照真相源自检：改动有没有超范围、有没有偏离原话或接口契约。
9. 通过后按 `../09-git/Git提交纪律.md` 做 checkpoint:**每个任务都提交 + push 到功能分支**(定时审查只看已提交的),并回写任务状态。
10. 进入下一个任务。

## 自检节奏（内部第一道防线）

满足任一条件立即自检（重读真相源 + 跑验收/测试 + 写执行反馈）：

- 完成一个任务。
- 连续改动超过约 10 个文件或一大块逻辑。
- 准备做任何接近禁止范围的事。
- 对需求或边界产生任何不确定。

## 定时测试（外部兜底）

按 `../07-testing/定时测试方案.md` 配置：

- 跑 Claude：用 `../07-testing/ClaudeCode定时任务提示词.md`（Claude Code `/schedule`）。
- 跑 Codex：用 `../07-testing/CodexApp定时测试提示词.md`（Codex App 自动化）。

定时测试发现 RED 时，执行 AI 必须停下，按报告处理偏离后再继续。

## 护栏（硬执行）

本项目装了护栏（见 `../10-guards/护栏说明.md`）：改任务允许范围外的文件、改用户原话、提交格式不对、push 到 main，会被直接拦下。跑 Claude 有实时 hook + git 双层；跑 Codex 靠 git hook（提交时），所以更要每个任务都提交。护栏靠 `current-task.json` 判定范围——每个任务第 0 步先更新它。

## 停止条件

- 任务边界不清楚。
- 需求没有来源原话或确认文件。
- 需要修改禁止范围。
- 验收标准缺失或无法验证。
- 发现用户原话与任务冲突。
- 定时测试报告 RED 未处理。
