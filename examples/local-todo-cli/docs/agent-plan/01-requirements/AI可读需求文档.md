# AI 可读需求文档

## 文档规则

- 本文档给 AI 代理执行和审查使用。
- 所有需求必须追溯到用户原话或用户确认的文件。
- 不允许把推测写成确认需求。
- 未确认内容必须写入 `开放问题.md`。

## 需求列表

### REQ-0001

需求 ID：REQ-0001

来源原话 ID：UW-0001

来源文件：—

用户意图：在命令行管理待办:加、删、列出。

AI 可执行需求：提供三个子命令——`add <文本>` 追加一条任务;`list` 列出全部(带编号);`del <编号>` 按编号删除一条。

硬约束：删除按**编号**(用户原话:「删的时候按编号删」)。编号为 list 显示的序号。

禁止行为：不得新增用户没要求的命令(如编辑、优先级、提醒)——那属于发散。

事实来源：任务数据来自本地 `todo.json`(见 REQ-0002)。

假设：编号从 1 开始,按文件中的顺序。

开放问题：无。

验收标准：`add` 后 `list` 能看到该条;`del N` 后该条消失、其余保留。

关联架构：命令解析器、任务存储。

关联任务：T-P0-0002。

### REQ-0002

需求 ID：REQ-0002

来源原话 ID：UW-0001

来源文件：—

用户意图：数据存本地,不要数据库、不要联网。

AI 可执行需求：所有任务持久化到运行目录下的单个文件 `todo.json`(UTF-8、JSON 数组)。读不到/损坏时按空列表处理并重建。

硬约束：**只用本地文件**;禁止数据库、禁止任何网络访问(见 禁止偏离事项 FB-0001/FB-0002)。

禁止行为：引入 db 依赖、发网络请求。

事实来源：`todo.json` 是任务的唯一真相源。

假设：单用户、单机、无并发写。

开放问题：无。

验收标准：`add` 后 `todo.json` 出现该条;删除后文件同步更新;全程无网络调用、无 db 依赖。

关联架构：任务存储。

关联任务：T-P0-0001。
